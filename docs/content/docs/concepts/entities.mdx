Every stored entity has a TypeID and embeds `types.Entity` for its timestamps. The structs below are copied from the code with their JSON tags left off; the Go packages are the source of truth.

## Base entity

```go
// package types
type Entity struct {
	CreatedAt time.Time
	UpdatedAt time.Time
}
```

`types.NewEntity()` stamps both with the current UTC time, and `Touch()` moves `UpdatedAt`. The ID is a field on each entity, not on `Entity`.

## Plan

```go
// package plan
type Plan struct {
	types.Entity
	ID           id.PlanID
	Name         string
	Slug         string            // unique within the app
	Description  string
	Currency     string            // lowercase ISO 4217, fixed once created
	Status       Status            // draft, active, archived
	TrialDays    int
	Features     []Feature
	Pricing      *Pricing
	Credits      []CreditPool // usage credit included each period
	AppID        string
	ProviderID   string
	ProviderName string
	Metadata     map[string]string
}

type Feature struct {
	types.Entity
	ID        id.FeatureID
	CatalogID id.FeatureID // optional link to a catalog feature
	Key       string       // what Entitled and Meter name
	Name      string
	Type      FeatureType  // metered, boolean, seat
	Limit     int64        // -1 for unlimited
	Period    Period       // monthly, yearly, none: the quota window
	SoftLimit bool
	Metadata  map[string]string
}

type Pricing struct {
	types.Entity
	ID            id.PriceID
	PlanID        id.PlanID
	BaseAmount    types.Money
	BillingPeriod Period // monthly or yearly; how often subscriptions roll
	Tiers         []PriceTier
}

type PriceTier struct {
	FeatureKey string
	Type       TierType    // graduated, volume, flat
	UpTo       int64       // total usage this tier reaches; 0 or -1 is open-ended
	UnitAmount types.Money // graduated and volume
	FlatAmount types.Money // flat
	Priority   int         // breaks ties between tiers with the same UpTo
}
```

See [Plans and pricing](/docs/subsystems/plans).

## Catalog feature

The catalog is a separate list of reusable feature definitions, per app or global. A plan's quota checks and invoices read the plan's own `Features`, not the catalog.

```go
// package feature
type Feature struct {
	types.Entity
	ID           id.FeatureID
	Key          string
	Name         string
	Description  string
	Type         FeatureType // metered, boolean, seat
	DefaultLimit int64
	Period       Period
	SoftLimit    bool
	Status       Status      // draft, active, archived
	AppID        string      // empty for a global feature
	ProviderID   string
	ProviderName string
	Metadata     map[string]string
}
```

## Subscription

```go
// package subscription
type Subscription struct {
	types.Entity
	ID                 id.SubscriptionID
	TenantID           string
	PlanID             id.PlanID
	Status             Status // active, trialing, past_due, canceled, expired, paused
	CurrentPeriodStart time.Time
	CurrentPeriodEnd   time.Time
	TrialStart         *time.Time
	TrialEnd           *time.Time
	CanceledAt         *time.Time
	CancelAt           *time.Time // a scheduled cancel
	EndedAt            *time.Time
	PausedAt           *time.Time
	Stretch            *Stretch   // the latest pause's effect on the period; not in JSON
	AppID              string
	ProviderID         string
	ProviderName       string
	Metadata           map[string]string
	Quantity           map[string]int64 // seat counts, by seat feature key
}
```

See [Subscriptions](/docs/subsystems/subscriptions).

## Entitlement result

```go

type Result struct {
```

## Invoice

```go
// package invoice
type Invoice struct {
	types.Entity
	ID             id.InvoiceID
	TenantID       string
	SubscriptionID id.SubscriptionID
	Status         Status // draft, pending, paid, past_due, voided
	Currency       string
	Subtotal       types.Money
	TaxAmount      types.Money
	DiscountAmount types.Money
	CreditAmount   types.Money // plan credit pools applied to usage
	Total          types.Money
	LineItems      []LineItem
	PeriodStart    time.Time
	PeriodEnd      time.Time
	DueDate        *time.Time
	PaidAt         *time.Time
	VoidedAt       *time.Time
	VoidReason     string
	PaymentRef     string
	ProviderID     string
	ProviderName   string
	AppID          string
	Metadata       map[string]string
}

type LineItem struct {
	ID          id.LineItemID
	InvoiceID   id.InvoiceID
	FeatureKey  string
	Description string
	Quantity    int64
	UnitAmount  types.Money
	Amount      types.Money
	Type        LineItemType // base, usage, overage, seat, discount, tax
	Metadata    map[string]string
}
```

`GenerateInvoice` writes `base`, `overage`, `seat`, `discount` and `tax` lines. `usage` is declared but the engine doesn't produce it. See [Invoicing](/docs/subsystems/invoicing).

## Coupon

```go
// package coupon
type Coupon struct {
	types.Entity
	ID             id.CouponID
	Code           string // unique within the app
	Name           string
	Type           CouponType  // percentage, amount
	Amount         types.Money // for amount coupons
	Percentage     int         // for percentage coupons, 0 to 100
	Currency       string
	MaxRedemptions int         // 0 or less means unlimited
	TimesRedeemed  int
	ValidFrom      *time.Time
	ValidUntil     *time.Time
	AppID          string
	Metadata       map[string]string
}

type Application struct {
	ID             id.CouponApplicationID
	CouponID       id.CouponID
	SubscriptionID id.SubscriptionID
	AppliedAt      time.Time
}
```

See [Coupons](/docs/subsystems/coupons).

## How they relate

```
Plan (AppID)
  ├── Feature[]        quota and allowance per feature key
  ├── Pricing          base fee, billing period, PriceTier[] per feature key
  └── CreditPool[]     usage credit per period, spent on metered features

Subscription (TenantID, AppID) ──> Plan
  ├── Quantity         seat counts
  ├── Coupon[]         through coupon applications
  └── Invoice[]        one live invoice per billed period
        └── LineItem[]

UsageEvent (TenantID, AppID, FeatureKey)
  totalled per feature for quota checks and invoices
```

There's no customer entity. The tenant ID on a subscription is the customer, and anything else you know about them stays in your own tables or in `Metadata`.

## Money

```go
// package types
type Money struct {
	Amount   int64  // smallest currency unit: cents, pence, yen
	Currency string // lowercase ISO 4217: "usd", "eur", "gbp"
}
```

Constructors: `types.USD`, `EUR`, `GBP`, `JPY`, `CAD`, `AUD` and `Zero(currency)`. The root package re-exports them as `ledger.USD` and so on. `Add`, `Subtract`, `Min`, `Max`, `LessThan` and `GreaterThan` panic when the currencies differ; the `Checked*` variants return an error instead and also catch `int64` overflow. `String()` gives `"$49.99"`, `FormatMajor()` gives `"49.99"`, and JSON adds a `display` field next to `amount` and `currency`.

## Store interfaces

Each entity package defines a store interface for its own methods (`plan.Store`, `subscription.Store`, `meter.Store` and so on). The one a store has to implement is `store.Store`, which lists every method with entity-prefixed names (`CreatePlan`, `IngestBatch`, `GetCached`, `CreateInvoice`, `RedeemCoupon` and the rest), the lifecycle queries, and `Migrate`, `Ping` and `Close`. See [Custom store](/docs/guides/custom-store).
