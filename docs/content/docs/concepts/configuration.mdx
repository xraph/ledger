title: Configuration
description: The engine's functional options, and the YAML keys the Forge extension reads.
---

Ledger has no config file, environment variables or config package of its own. You configure the engine with functional options passed to `ledger.New`. If you run it through the Forge extension, the extension reads a few YAML keys and turns them into those same options.

## Engine options

```go
engine := ledger.New(store,
	ledger.WithLogger(logger),                      // a go-utils log.Logger
	ledger.WithMeterConfig(100, 5*time.Second),     // batch size, flush interval
	ledger.WithEntitlementCacheTTL(30*time.Second),
	ledger.WithLifecycleInterval(time.Minute),
	ledger.WithPlugin(myPlugin),
)
```

| Option | Default | What it does |
|--------|---------|--------------|
| `WithLogger(log.Logger)` | a no-op logger | Sets the logger for the engine and the plugin registry. It takes a `github.com/xraph/go-utils/log` `Logger`, not a `*slog.Logger`. |
| `WithPlugin(plugin.Plugin)` | none | Registers a plugin. A second plugin with the same `Name()` is dropped without an error. |
| `WithMeterConfig(batchSize int, flushInterval time.Duration)` | `100`, `5s` | The flush worker writes a batch once it holds `batchSize` events, or every `flushInterval`, whichever comes first. Keep both positive: `Start` panics on a zero or negative interval. |
| `WithEntitlementCacheTTL(time.Duration)` | `30s` | How long a quota answer stays in the store's entitlement cache. `0` makes every entry expire at once. |
| `WithLifecycleInterval(time.Duration)` | `1m` | How often the background lifecycle clock calls `Advance`. Zero or less turns the clock off. |
| `WithClock(func() time.Time)` | `time.Now` | Where the engine reads the time for lifecycle runs, new subscription periods and trials, invoice periods, coupon validity and due dates. Tests use it. A nil clock is ignored. |
| `WithMetrics(metrics.Metrics)` | no metrics | Records the engine's metrics, and failed plugin hook calls, on a `github.com/xraph/go-utils/metrics` `Metrics`. The Forge extension passes `app.Metrics()`. Spans need no option. See [Observability](/docs/guides/observability). |
| `WithoutMigrate()` | migrate on | `Start` skips `store.Migrate` and only starts the workers. Use it when you migrate the schema separately. |

A few things aren't configurable. The meter buffer holds 10,000 events, and `Meter` returns `ledger.ErrMeterBufferFull` once it's full. `FinalizeInvoice` always sets a due date 30 days out. Each plugin hook gets 5 seconds before the registry stops waiting on it.

## Forge extension config

The [Forge extension](/docs/guides/forge-extension) reads YAML under `extensions.ledger`, and falls back to a top-level `ledger` key:

```yaml
extensions:
  ledger:
    grove_database: ""          # named grove.DB in the container; empty uses the default one
    disable_migrate: false
    meter_batch_size: 100
    meter_flush_interval: 5s
    entitlement_cache_ttl: 30s
    lifecycle_interval: 1m
    disable_lifecycle: false
    app_id: ""                  # scopes the dashboard contributor to one app
    require_app_claim: false
```

| YAML key | Type | Default | Option | What it does |
|----------|------|---------|--------|--------------|
| `grove_database` | string | `""` | `WithGroveDatabase(name)` | Resolves the `*grove.DB` registered under this name and builds the matching store. See [store resolution](/docs/guides/forge-extension#store-resolution). |
| `disable_migrate` | bool | `false` | `WithDisableMigrate()` | Passes `ledger.WithoutMigrate()` to the engine. |
| `meter_batch_size` | int | `100` | `WithMeterBatchSize(n)` | The batch size half of `WithMeterConfig`. |
| `meter_flush_interval` | duration | `5s` | `WithMeterFlushInterval(d)` | The interval half of `WithMeterConfig`. |
| `entitlement_cache_ttl` | duration | `30s` | `WithEntitlementCacheTTL(d)` | Passed to `ledger.WithEntitlementCacheTTL`. |
| `lifecycle_interval` | duration | `1m` | none | Passed to `ledger.WithLifecycleInterval`. Zero or a negative value means the default, not off. |
| `disable_lifecycle` | bool | `false` | `WithDisableLifecycle()` | Turns the lifecycle clock off, for a deployment that calls `Advance` from its own scheduler. |
| `app_id` | string | `""` | `WithAppID(id)` | The app the dashboard contributor serves when the caller's principal carries no `app_id` claim. |
| `require_app_claim` | bool | `false` | none | Makes the dashboard contributor refuse a request whose principal has no `app_id` claim. Turn it on in a multi-app deployment. |
| `base_path` | string | `""` | `WithBasePath(path)` | Does nothing. Ledger registers no HTTP routes, so there is no prefix to apply. |
| `disable_routes` | bool | `false` | `WithDisableRoutes()` | Does nothing, for the same reason. |

Two keys have no matching extension option. To set them in code, use `WithConfig(extension.Config{...})`, or pass the engine option straight through with `WithLedgerOption(ledger.WithLifecycleInterval(d))`.

### How YAML and options merge

When the extension finds YAML, it merges it with whatever you set in code:

1. Strings, numbers and durations from YAML win. A programmatic value fills a key YAML leaves empty or zero.
2. A boolean set to `true` in code wins over YAML. YAML can't turn a programmatic `true` back off.
3. Anything still zero gets the default from `extension.DefaultConfig()`.

When no YAML is found, the programmatic config is used with the same defaults. `WithRequireConfig(true)` makes `Register` fail instead when neither `extensions.ledger` nor `ledger` exists.

`WithConfig(cfg)` replaces the whole programmatic config, so put it before any `WithXxx` option you want to keep.

### Options that only exist in code

| Option | What it does |
|--------|--------------|
| `WithStore(store.Store)` | Uses this store and skips Grove resolution. |
| `WithPlugin(plugin.Plugin)` | Registers a Ledger plugin. |
| `WithLedgerOption(ledger.Option)` | Passes any engine option through. These are applied after the config-derived ones, so they win. |
| `WithConfig(extension.Config)` | Sets the whole config struct. |
| `WithRequireConfig(bool)` | Fails `Register` when no YAML config exists. |
