---
title: Invoice Generation
description: What GenerateInvoice puts on an invoice, the invoice's statuses, and how to export it.
---

`GenerateInvoice` bills one period of one subscription. It reads the plan as it is now, counts the usage inside the period, and writes a draft invoice with its line items.

```go
inv, err := engine.GenerateInvoice(ctx, sub.ID)                           // the current period
inv, err = engine.GenerateInvoice(ctx, sub.ID, ledger.ForPeriod(start, end)) // a period that has ended
```

Ledger never calls it for you. You decide when a period gets billed: usually from an `OnSubscriptionRenewed` hook, which lists the periods that just ended, or from your own scheduled job. See [Billing cycles](/docs/subsystems/billing-cycles).

## Line items

The lines are built in a fixed order:

| Order | Type | Description | Amount |
|-------|------|-------------|--------|
| 1 | `base` | "Base subscription fee" | `Pricing.BaseAmount`, when it's above zero |
| 2 | `overage` | "&lt;feature name&gt; overage" | One per metered feature whose usage in the period passed its `Limit`, priced by its tiers. `Quantity` is the units past the limit |
| 3 | `seat` | the feature name | One per seat feature with a seat count above zero, priced by its tiers. `Quantity` is the seat count |
| 4 | `credit` | "&lt;pool key&gt; credit" | One per plan credit pool that has usage to cancel, as a negative amount. See [credit pools](/docs/subsystems/plans#credit-pools) |
| 5 | `discount` | "Discount &lt;code&gt;" | One per applied coupon, as a negative amount |
| 6 | `tax` | "Tax" | The sum from every `TaxCalculator` plugin, when it's above zero |

A line that prices at zero is left off. Overage and seat lines carry the feature key, and their `UnitAmount` is zero, because a tiered price has no single unit rate. `invoice.LineItemUsage` is declared but never used.

The totals:

- `Subtotal` is base plus overage plus seats.
- `CreditAmount` is the sum of the credit pool lines.
- `DiscountAmount` is the sum of the coupons. A percentage coupon takes its share of the subtotal less credit, before any coupon, rounded down to the cent, so two percentage coupons don't compound.
- Tax is computed on the subtotal less credit and discounts, never below zero.
- `Total` is that net amount plus `TaxAmount`. Credit and discount together larger than the bill give a zero total, never a negative one.

Every amount is in the plan's currency, lowercased. Every sum is overflow-checked: an amount that doesn't fit in an `int64` fails generation with an error wrapping `types.ErrOverflow`, and nothing is stored.

## What gets billed

- Usage is the period's own: the events from its start to its end, or to now while it's still running.
- Everything else is current: the plan, its prices, the seat counts and the applied coupons are read as they are when you call it. Ledger keeps no history of them, so a plan change in the middle of a period prices the whole period on the new plan. There's no proration.
- A metered feature with `Limit: -1` never bills, and its tiers aren't checked.
- Trials aren't skipped. A period inside a trial bills its base fee if you invoice it.

## When it refuses

| Error | Why |
|-------|-----|
| `ErrInvalidInput` | The subscription has no tenant; it's paused (its current period's end will still move); or the `ForPeriod` period isn't one the subscription has had |
| `ErrAlreadyExists` | A live (not voided) invoice already covers this subscription and period |
| `ErrInvalidPricing` | The base price is negative or in another currency |
| `invoice.ErrInvalidTiers` | A feature's tiers are broken |
| `ErrCouponInvalid` | An applied coupon no longer fits: wrong currency, bad percentage, unknown type |
| `types.ErrOverflow` | A sum doesn't fit in an `int64` |

Voiding an invoice frees its period, so you can generate a replacement.

## Billing a past period

`ForPeriod(start, end)` bills a period the subscription has already had: the one the lifecycle clock just rolled past, or one a catch-up skipped. The period has to be the current one or one before it on the subscription's cadence, it has to have started, and it has to end after the subscription was created. Anything else fails with `ErrInvalidInput`.

```go
func (b *biller) OnSubscriptionRenewed(ctx context.Context, renewal interface{}) error {
	r := renewal.(*subscription.Renewal)
	for _, p := range r.Ended {
		_, err := b.engine.GenerateInvoice(ctx, r.Subscription.ID, ledger.ForPeriod(p.Start, p.End))
		if err != nil && !errors.Is(err, ledger.ErrAlreadyExists) {
			return err
		}
	}
	return nil
}
```

## Statuses

```
draft ──FinalizeInvoice──> pending ──MarkInvoicePaid──> paid
  │                          │
  │                          └── due date passes (lifecycle clock) ──> past_due
  │
  └──────── MarkInvoiceVoided (from draft, pending or past_due) ──> voided
```

| Call | From | Effect | Hook |
|------|------|--------|------|
| `FinalizeInvoice(ctx, invID)` | `draft` only, else `ErrInvoiceFinalized` | `pending`, `DueDate` 30 days out | `OnInvoiceFinalized` |
| `MarkInvoicePaid(ctx, invID, paidAt, paymentRef)` | anything but `paid` or `voided` | `paid`, with `PaidAt` and `PaymentRef` | `OnInvoicePaid` |
| `MarkInvoiceVoided(ctx, invID, reason)` | anything but `paid` or `voided` | `voided`, with `VoidedAt` and `VoidReason` | `OnInvoiceVoided` |
| lifecycle clock | `pending` past its due date | `past_due` | `OnInvoicePastDue` |

`MarkInvoicePaid` also accepts a `past_due` or even a `draft` invoice. `OnInvoiceFailed` is declared in the plugin package but never fires: Ledger doesn't collect payments, so it never sees one fail.

## Exporting

`ExportInvoice(ctx, invID, format)` renders an invoice through the `InvoiceFormatter` plugin registered for that format, and `InvoiceFormats()` lists the formats you've registered. No formatter ships with the module, so with none registered, export fails with `ErrInvalidInput`.

```go
pdf, err := engine.ExportInvoice(ctx, inv.ID, "pdf")
```

## Reading invoices

```go
inv, err := engine.Store().GetInvoice(ctx, invID)
invs, err := engine.Store().ListInvoices(ctx, "acme", "my-app", invoice.ListOpts{Status: invoice.StatusPending})
pending, err := engine.Store().ListPendingInvoices(ctx, "my-app")
```

## Remote access

Ledger has no HTTP routes for invoices. The Forge dashboard uses the contract intents `invoices.list`, `invoices.detail`, `invoices.pending`, `invoices.export`, `invoices.generate`, `invoices.finalize`, `invoices.markPaid` and `invoices.void`. See [HTTP API](/docs/api-reference/http-api).
