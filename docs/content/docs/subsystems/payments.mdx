---
title: Payment Providers
description: The provider interface you implement to connect Stripe, Paddle or another gateway, and what the engine does with it.
---

Ledger doesn't take payments. It works out what a tenant owes and tracks the invoice from draft to paid, and collecting the money is up to you and your payment gateway. What Ledger gives you is an interface, `provider.Provider`, that lets the engine push plans, subscriptions and invoices to a gateway, pull them back, list payment methods and route webhooks.

A Stripe provider ships in `provider/stripe`, and [its page](/docs/subsystems/stripe) covers setup, webhooks and refunds. For Paddle or any other gateway, you write the implementation yourself against the interface below.

## The interface

```go
// package provider
type Provider interface {
	Name() string

	// Payment methods are fetched live and never stored.
	ListPaymentMethods(ctx context.Context, tenantID string) ([]PaymentMethod, error)

	// Push a local entity to the provider; return the provider's ID for it.
	SyncPlan(ctx context.Context, p *plan.Plan) (providerID string, err error)
	SyncFeature(ctx context.Context, f *feature.Feature) (providerID string, err error)
	SyncSubscription(ctx context.Context, s *subscription.Subscription) (providerID string, err error)
	SyncInvoice(ctx context.Context, inv *invoice.Invoice) (providerID string, err error)

	// Pull an entity from the provider by its ID there.
	ImportPlan(ctx context.Context, providerID string) (*plan.Plan, error)
	ImportFeature(ctx context.Context, providerID string) (*feature.Feature, error)
	ImportSubscription(ctx context.Context, providerID string) (*subscription.Subscription, error)
	ImportInvoice(ctx context.Context, providerID string) (*invoice.Invoice, error)

	// Handle an incoming webhook payload.
	HandleWebhook(ctx context.Context, payload []byte) (*WebhookResult, error)
}
```

`PaymentMethod`, `SyncResult` and `WebhookResult` are plain structs in the same package. See [Go packages](/docs/api-reference/go-packages#githubcomxraphledgerprovider).

## Registering a provider

A provider reaches the engine as a plugin that implements `plugin.PaymentProviderPlugin`:

```go
type stripePlugin struct{ p *StripeProvider }

func (s *stripePlugin) Name() string                { return "stripe" }
func (s *stripePlugin) Provider() provider.Provider { return s.p }

engine := ledger.New(store, ledger.WithPlugin(&stripePlugin{p: NewStripeProvider(apiKey)}))
```

You can register more than one. Calls that take a provider name use the one whose `Provider().Name()` matches; calls that don't use the first one registered. `ProviderNames()` and `HasProviders()` tell you what's there.

## What the engine does with it

| Method | Does |
|--------|------|
| `ListPaymentMethods(ctx, tenantID)` | Asks the first provider. Returns an empty list, not an error, when none is registered. |
| `SyncPlanToProvider(ctx, planID)` | Calls `SyncPlan` on the provider named in the plan's `ProviderName`, or the first one. On success, stores the provider's ID and name on the plan. |
| `SyncFeatureToProvider`, `SyncSubscriptionToProvider`, `SyncInvoiceToProvider` | The same for those entities. Subscription and invoice syncs write only the provider columns, so a lifecycle change landing during the network call survives. |
| `ImportPlanFromProvider(ctx, providerName, providerID, opts...)` | Pulls a plan and creates it through `CreatePlan`, so it's validated like any other. A slug the app already uses fails with `ErrAlreadyExists`, which is also what stops a second import of the same plan. |
| `ImportFeatureFromProvider`, `ImportSubscriptionFromProvider`, `ImportInvoiceFromProvider` | The same for those entities, each with its own checks. |
| `HandleWebhook(ctx, providerName, payload)` | Fires `OnWebhookReceived`, then passes the payload to the provider's `HandleWebhook`. A provider error comes back wrapped in `ErrProviderWebhook`. |

Each sync returns a `*provider.SyncResult` and fires `OnProviderSync`. Every sync, import or webhook call fails with `ErrProviderNotConfigured` when no provider is registered, and `ErrProviderNotFound` when the named one isn't.

Imports take `ledger.ImportInto(appID)` to file the record under an app. The provider interface has no idea of apps, so without it the record keeps whatever app the provider reported. A record the provider files under a different app is refused.

`HandleWebhook` doesn't apply anything to Ledger's own data. Your provider's `HandleWebhook` verifies the payload and does whatever the event calls for, such as calling `engine.MarkInvoicePaid` when a charge succeeds.

## Serving webhooks

Ledger has no webhook endpoint. Mount one on your own router and hand the body to the engine:

```go
mux.HandleFunc("POST /webhooks/stripe", func(w http.ResponseWriter, r *http.Request) {
	payload, err := io.ReadAll(r.Body)
	if err != nil {
		http.Error(w, "bad body", http.StatusBadRequest)
		return
	}
	if _, err := engine.HandleWebhook(r.Context(), "stripe", payload); err != nil {
		http.Error(w, "rejected", http.StatusBadRequest)
		return
	}
	w.WriteHeader(http.StatusOK)
})
```

`HandleWebhook` receives only the body, so a provider that verifies a signature from a request header needs it some other way: verify in the handler before calling the engine, or put the header in the context for your provider to read.

## Recording a payment

Whatever collects the money, record it on the invoice:

```go
err := engine.MarkInvoicePaid(ctx, invID, paidAt, "pi_3Nx...") // the provider's payment reference
```

That sets `PaidAt` and `PaymentRef` and fires `OnInvoicePaid`. There's no refund, retry or dunning logic in the engine, and no payment entity: `id.PrefixPayment` is reserved but unused.

## Remote access

The Forge dashboard uses the contract intents `paymentMethods.list` and the `*.syncToProvider` and `*.importFromProvider` commands for plans, features, subscriptions and invoices. See [HTTP API](/docs/api-reference/http-api).
