title: Forge Extension
description: Register Ledger with a Forge app, pick its store, and use the engine from your handlers.
---

The `extension` package wraps the engine as a [Forge](https://github.com/xraph/forge) extension. It builds the engine when the app registers its extensions, puts `*ledger.Ledger` in the DI container, starts and stops it with the app, reports the store's health, and registers a contract contributor for the Forge dashboard.

It doesn't mount any HTTP routes, and it doesn't read the tenant from Forge's request scope. Your handlers call the engine and set the tenant context themselves, as shown [below](#use-the-engine-in-a-handler).

## Register the extension

```go
package main

import (
	"log"
	"time"

	"github.com/xraph/forge"

	ledgerext "github.com/xraph/ledger/extension"
)

func main() {
	app := forge.NewApp(forge.AppConfig{
		Name:    "billing",
		Version: "1.0.0",
		Extensions: []forge.Extension{
			ledgerext.New(ledgerext.WithMeterFlushInterval(2 * time.Second)),
		},
	})

	if err := app.Run(); err != nil {
		log.Fatal(err)
	}
}
```

You can also call `app.RegisterExtension(ext)` on an app you've already built.

## Lifecycle

| Phase | What the extension does |
|-------|-------------------------|
| `Register` | Loads config, picks a store, builds the engine with `ledger.New`, and provides `*ledger.Ledger` to the container. |
| `Start` | Calls `engine.Start`, which migrates the store unless migration is disabled, then starts the meter flush worker and the lifecycle clock. |
| `Health` | Pings the store. |
| `Stop` | Calls `engine.Stop`, which stops the workers and closes the store. |

`Engine()` returns the engine, and it's nil until `Register` has run.

## Store resolution

The extension picks its store in this order:

1. `WithStore(s)`, if you passed one.
2. A `*grove.DB` from the container, when you set `WithGroveDatabase(name)` or the `grove_database` YAML key. A non-empty name resolves that named database; `WithGroveDatabase("")` resolves the default one. If it isn't there, `Register` fails.
3. The default `*grove.DB` in the container, if there is one, even when you set nothing.
4. The in-memory store. Fine for a demo, but nothing survives a restart.

For a Grove database, the driver's name picks the store: `pg` gives `store/postgres`, `sqlite` gives `store/sqlite` and `mongo` gives `store/mongo`. Any other driver fails `Register`. You don't import the store packages yourself.

```go
ledgerext.New(ledgerext.WithGroveDatabase("billing")) // the grove.DB named "billing"
ledgerext.New(ledgerext.WithGroveDatabase(""))        // the default grove.DB, or fail
```

## Use the engine in a handler

Resolve the engine from the container, or keep a handle on the extension and call `Engine()` at request time. Then put the tenant and app into the request's context under the string keys `"tenant_id"` and `"app_id"`, which is where `Entitled`, `Remaining` and `Meter` read them:

```go
ext := ledgerext.New()
app := forge.NewApp(forge.AppConfig{
	Name:       "api",
	Extensions: []forge.Extension{ext},
})

_ = app.Router().GET("/reports", func(c forge.Context) error {
	engine := ext.Engine() // or forge.Inject[*ledger.Ledger](app.Container())

	// Take the tenant from your own auth. A header keeps the example short.
	ctx := context.WithValue(c.Context(), "tenant_id", c.Header("X-Tenant-ID"))
	ctx = context.WithValue(ctx, "app_id", "my-app")

	res, err := engine.Entitled(ctx, "reports")
	if err != nil {
		return err
	}
	if !res.Allowed {
		return c.JSON(http.StatusTooManyRequests, res)
	}

	// Do the work, then record it.
	if err := engine.Meter(ctx, "reports", 1); err != nil {
		return err
	}

	return c.JSON(http.StatusOK, map[string]any{"remaining": res.Remaining})
})
```

Other extensions and services can resolve it the same way with `forge.Inject[*ledger.Ledger](app.Container())` once the extension has registered.

## Plugins

`WithPlugin` registers a Ledger plugin, and `WithLedgerOption` passes any engine option through. Two plugins come with the module:

```go
recorder := audithook.RecorderFunc(func(ctx context.Context, ev *audithook.AuditEvent) error {
	log.Printf("audit %s %s %s", ev.Action, ev.ResourceID, ev.Outcome)
	return nil
})

ext := ledgerext.New(
	ledgerext.WithPlugin(audithook.New(recorder)),
	ledgerext.WithPlugin(observability.NewMetricsExtension(factory)),
	ledgerext.WithLedgerOption(ledger.WithLifecycleInterval(30*time.Second)),
)
```

`audithook` lives at `github.com/xraph/ledger/audit_hook`. `observability.NewMetricsExtension` takes an `observability.MetricFactory`, a two-method interface (`Counter(name)` and `Histogram(name)`) you adapt to your metrics backend. See [Custom plugin](/docs/guides/custom-plugin#built-in-plugins).

The extension already hands the engine its own logger, so you only need `WithLedgerOption(ledger.WithLogger(...))` to replace it. It hands over the app's metrics the same way: the engine's spans go to Forge's tracer provider and its metrics land on `/_/metrics` as `forge_ledger_...`, with nothing for you to wire. [Observability](/docs/guides/observability) lists them. You don't need the `observability` plugin for any of that.

## YAML configuration

The extension reads `extensions.ledger`, then falls back to `ledger`:

```yaml
extensions:
  ledger:
    grove_database: billing
    disable_migrate: false
    meter_batch_size: 100
    meter_flush_interval: 5s
    entitlement_cache_ttl: 30s
    lifecycle_interval: 1m
    disable_lifecycle: false
    app_id: my-app
    require_app_claim: false
```

`base_path` and `disable_routes` exist in the config struct (with `WithBasePath` and `WithDisableRoutes`), but they do nothing, because the extension registers no routes. [Configuration](/docs/concepts/configuration#forge-extension-config) has every key, its default, and how YAML merges with options. In short, YAML wins for strings and numbers, a programmatic `true` wins for booleans, and `WithRequireConfig(true)` makes `Register` fail when there's no YAML at all.

## Dashboard contributor

`RegisterContractContributor` is what the Forge dashboard calls during its own start to find Ledger. It registers queries and commands for plans, features, subscriptions, usage, entitlements, invoices, coupons, payment methods, an overview and settings, under the capabilities `ledger.read` and `ledger.write`. You don't call it yourself.

Each request is scoped to one app: the `app_id` claim on the caller's principal, or `app_id` from config when there's no claim. With `require_app_claim: true`, a request without the claim is refused. The pages that call these intents live in forge-dashboard's `plugin-ledger` package. [HTTP API](/docs/api-reference/http-api) lists the intents.
