---
title: Custom Plugin
description: Hook into billing events, replace pricing, usage totals, tax or export formats, and use the two plugins that ship with Ledger.
---

A plugin is any value with a `Name()` method. It opts into events by implementing hook interfaces from the `plugin` package, and into parts of the billing logic by implementing strategy interfaces. You register it with `ledger.WithPlugin`.

## Plugin basics

```go
package plugin

type Plugin interface {
	Name() string
}
```

`Name()` must be unique. Registering a second plugin with the same name does nothing: `WithPlugin` drops it without an error, so check your names.

The registry looks at each plugin once, at registration, and files it under every hook and strategy interface it implements. Implement only what you need.

## Hooks

Hook arguments are typed `interface{}` so the `plugin` package doesn't import the entity packages. The table lists what the engine actually passes, so you can type-assert.

### System

| Interface | Method | Fires | Argument |
|-----------|--------|-------|----------|
| `OnInit` | `OnInit(ctx, l)` | In `Start`, after migration | `*ledger.Ledger` |
| `OnShutdown` | `OnShutdown(ctx)` | In `Stop`, after the workers stop | |

### Plans and catalog features

| Interface | Method | Fires | Argument |
|-----------|--------|-------|----------|
| `OnPlanCreated` | `OnPlanCreated(ctx, plan)` | `CreatePlan`, and a plan import | `*plan.Plan` |
| `OnPlanUpdated` | `OnPlanUpdated(ctx, oldPlan, newPlan)` | `UpdatePlan`, `ActivatePlan` | `*plan.Plan` twice |
| `OnPlanArchived` | `OnPlanArchived(ctx, planID)` | `ArchivePlan` | `string` |
| `OnFeatureCreated` | `OnFeatureCreated(ctx, f)` | `CreateFeature` | `*feature.Feature` |
| `OnFeatureUpdated` | `OnFeatureUpdated(ctx, oldF, newF)` | `UpdateFeature` | `*feature.Feature` twice |
| `OnFeatureArchived` | `OnFeatureArchived(ctx, featureID)` | `ArchiveFeature` | `string` |
| `OnFeatureDeleted` | `OnFeatureDeleted(ctx, featureID)` | `DeleteFeature` | `string` |

### Subscriptions

| Interface | Method | Fires | Argument |
|-----------|--------|-------|----------|
| `OnSubscriptionCreated` | `OnSubscriptionCreated(ctx, sub)` | `CreateSubscription` | `*subscription.Subscription` |
| `OnSubscriptionChanged` | `OnSubscriptionChanged(ctx, sub, oldPlan, newPlan)` | `ChangePlan` | subscription, then two `*plan.Plan` |
| `OnSubscriptionCancelScheduled` | `OnSubscriptionCancelScheduled(ctx, sub)` | `CancelSubscription(..., false)` | `*subscription.Subscription` |
| `OnSubscriptionCanceled` | `OnSubscriptionCanceled(ctx, sub)` | An immediate cancel, or the clock enacting a scheduled one | `*subscription.Subscription` |
| `OnSubscriptionRenewed` | `OnSubscriptionRenewed(ctx, renewal)` | The clock moving a period forward | `*subscription.Renewal` |
| `OnSubscriptionTrialEnded` | `OnSubscriptionTrialEnded(ctx, sub)` | The clock ending a trial | `*subscription.Subscription` |
| `OnSubscriptionExpired` | `OnSubscriptionExpired(ctx, sub)` | Never. Declared, not fired. | |

Pause and resume fire no hook.

### Usage and entitlements

| Interface | Method | Fires | Argument |
|-----------|--------|-------|----------|
| `OnUsageFlushed` | `OnUsageFlushed(ctx, count, elapsed)` | After each meter batch is written | `int`, `time.Duration` |
| `OnEntitlementChecked` | `OnEntitlementChecked(ctx, result)` | A metered or seat answer is computed (not a cache hit) | `*entitlement.Result` |
| `OnQuotaExceeded` | `OnQuotaExceeded(ctx, tenantID, featureKey, used, limit)` | A computed answer is `"quota exceeded"` | |
| `OnUsageIngested` | `OnUsageIngested(ctx, events)` | Never. Declared, not fired. | |
| `OnSoftLimitReached` | `OnSoftLimitReached(ctx, tenantID, featureKey, used, limit)` | Never. Declared, not fired. | |

### Invoices

| Interface | Method | Fires | Argument |
|-----------|--------|-------|----------|
| `OnInvoiceGenerated` | `OnInvoiceGenerated(ctx, inv)` | `GenerateInvoice`, and an invoice import | `*invoice.Invoice` |
| `OnInvoiceFinalized` | `OnInvoiceFinalized(ctx, inv)` | `FinalizeInvoice` | `*invoice.Invoice` |
| `OnInvoicePaid` | `OnInvoicePaid(ctx, inv)` | `MarkInvoicePaid` | `*invoice.Invoice` |
| `OnInvoiceVoided` | `OnInvoiceVoided(ctx, inv, reason)` | `MarkInvoiceVoided` | `*invoice.Invoice`, `string` |
| `OnInvoicePastDue` | `OnInvoicePastDue(ctx, inv)` | The clock marking an invoice past due | `*invoice.Invoice` |
| `OnInvoiceFailed` | `OnInvoiceFailed(ctx, inv, err)` | Never. Declared, not fired. | |

### Providers

| Interface | Method | Fires |
|-----------|--------|-------|
| `OnProviderSync` | `OnProviderSync(ctx, provider, success, err)` | After each sync, and after a failed or successful import |
| `OnWebhookReceived` | `OnWebhookReceived(ctx, provider, payload)` | In `HandleWebhook`, before the provider sees the payload |

## How hooks run

- Synchronously. The call that fires a hook waits for each plugin in turn, so a slow hook slows `CreatePlan`, the meter flush or the lifecycle clock.
- With a timeout. The registry stops waiting on a hook after five seconds, or when the caller's context is done, and moves on. The hook keeps running in its goroutine.
- Without consequences for the caller. A hook's error or timeout is logged at warn level and never fails the operation, which has already been written by then.
- Without panic recovery. Each hook runs in its own goroutine and nothing recovers a panic there, so a panicking hook takes the process down. Recover inside your hook if it can panic.
- Lifecycle hooks (renewed, canceled by the clock, trial ended, past due) run on a context without the run's cancel or deadline, so a `Stop` during a deploy doesn't cut them off.

If a hook does slow work, such as an HTTP call, hand it to a goroutine or a queue and return.

## Implementing hooks

```go
package myplugin

import (
	"context"
	"log/slog"

	"github.com/xraph/ledger/invoice"
	"github.com/xraph/ledger/plugin"
)

var (
	_ plugin.Plugin        = (*MyPlugin)(nil)
	_ plugin.OnInvoicePaid = (*MyPlugin)(nil)
)

type MyPlugin struct {
	logger *slog.Logger
}

func New(logger *slog.Logger) *MyPlugin { return &MyPlugin{logger: logger} }

func (p *MyPlugin) Name() string { return "my-plugin" }

func (p *MyPlugin) OnInvoicePaid(ctx context.Context, v interface{}) error {
	inv, ok := v.(*invoice.Invoice)
	if !ok {
		return nil
	}
	p.logger.InfoContext(ctx, "invoice paid", "invoice", inv.ID.String(), "total", inv.Total.String())
	return nil
}
```

The `var _ plugin.OnInvoicePaid = (*MyPlugin)(nil)` lines make the compiler check that the methods match.

Register it:

```go
engine := ledger.New(store,
	ledger.WithPlugin(myplugin.New(slog.Default())),
)
```

## Example: quota alerts to Slack

```go
type SlackAlerts struct {
	webhookURL string
	client     *http.Client
}

func (s *SlackAlerts) Name() string { return "slack-alerts" }

func (s *SlackAlerts) OnQuotaExceeded(_ context.Context, tenantID, featureKey string, used, limit int64) error {
	text := fmt.Sprintf("%s hit its %s quota: %d of %d", tenantID, featureKey, used, limit)
	go s.post(text) // don't hold up the quota check
	return nil
}

func (s *SlackAlerts) post(text string) {
	body, _ := json.Marshal(map[string]string{"text": text})
	resp, err := s.client.Post(s.webhookURL, "application/json", bytes.NewReader(body))
	if err != nil {
		return
	}
	_ = resp.Body.Close()
}
```

`OnQuotaExceeded` fires each time a "quota exceeded" answer is computed, not on cache hits, so you get at most one alert per tenant and feature per cache TTL.

## Strategy plugins

Strategy plugins replace part of the billing calculation. They're called synchronously, without the hook timeout, and an error or a wrong result fails the operation.

### PricingStrategy

```go
type PricingStrategy interface {
	Plugin
	StrategyName() string
	Compute(tiers []interface{}, usage, included int64, currency string) interface{} // returns types.Money
}
```

A plan feature names a strategy in its `Metadata` under `"pricing_strategy"`; failing that, the plan's own `Metadata` can name one for all its features. `GenerateInvoice` then calls `Compute` instead of the built-in tier models, for metered overage and for seats. It passes the feature's tiers sorted (as `plan.PriceTier` values), the total usage, the allowance (the feature's `Limit`, or 0 for seats) and the plan's currency, and only calls it when usage is above the allowance. The result must be a non-negative `types.Money` in that currency. An unregistered name logs a warning and falls back to the tiers.

```go
type PerUnit struct{ cents int64 }

func (p *PerUnit) Name() string         { return "per-unit-pricing" }
func (p *PerUnit) StrategyName() string { return "per-unit" }
func (p *PerUnit) Compute(_ []interface{}, usage, included int64, currency string) interface{} {
	return types.Money{Amount: (usage - included) * p.cents, Currency: currency}
}
```

### UsageAggregator

```go
type UsageAggregator interface {
	Plugin
	AggregatorName() string
	Aggregate(ctx context.Context, events []interface{}) (int64, error)
}
```

A metered plan feature names an aggregator in its `Metadata` under `"aggregator"`. `GenerateInvoice` then passes it the period's events for that feature (each a `*meter.UsageEvent`) and bills the total it returns, instead of the sum. The subscription must have an app ID, and a negative total fails the invoice. Quota checks don't use aggregators: they always sum.

```go
type Peak struct{}

func (Peak) Name() string           { return "peak-usage" }
func (Peak) AggregatorName() string { return "max" }
func (Peak) Aggregate(_ context.Context, events []interface{}) (int64, error) {
	var peak int64
	for _, e := range events {
		if ev, ok := e.(*meter.UsageEvent); ok && ev.Quantity > peak {
			peak = ev.Quantity
		}
	}
	return peak, nil
}
```

### TaxCalculator

```go
type TaxCalculator interface {
	Plugin
	CalculateTax(ctx context.Context, subtotal interface{}, tenantID string) (interface{}, error) // returns types.Money
}
```

Every registered tax calculator is called, and their amounts are added up into one tax line. The amount passed in is a `types.Money`: the subtotal less discounts, never below zero. Return a non-negative `types.Money` in the same currency, or nil for no tax. Keep the arithmetic in integers:

```go
type FlatRateTax struct{ basisPoints int64 } // 800 = 8%

func (t *FlatRateTax) Name() string { return "flat-rate-tax" }
func (t *FlatRateTax) CalculateTax(_ context.Context, v interface{}, _ string) (interface{}, error) {
	net, ok := v.(types.Money)
	if !ok {
		return nil, fmt.Errorf("unexpected amount type %T", v)
	}
	return types.Money{Amount: net.Amount * t.basisPoints / 10000, Currency: net.Currency}, nil
}
```

### InvoiceFormatter

```go
type InvoiceFormatter interface {
	Plugin
	Format() string                                                   // "pdf", "html", "csv"
	Render(ctx context.Context, inv interface{}, w interface{}) error // inv is *invoice.Invoice, w is an io.Writer
}
```

Formatters are filed by `Format()`. `engine.ExportInvoice(ctx, invID, format)` renders through the matching one, and `engine.InvoiceFormats()` lists them. No formatter ships with Ledger.

### CouponValidator

```go
type CouponValidator interface {
	Plugin
	ValidateCoupon(ctx context.Context, coupon interface{}, sub interface{}) error
}
```

`ApplyCoupon` calls every validator after its own checks, with the `*coupon.Coupon` and the `*subscription.Subscription`. Returning an error refuses the coupon, wrapped in `ErrCouponInvalid`. Validators don't run again at invoice time.

### PaymentProviderPlugin

```go
type PaymentProviderPlugin interface {
	Plugin
	Provider() provider.Provider
}
```

See [Payment providers](/docs/subsystems/payments).

## Built-in plugins

### audithook

`github.com/xraph/ledger/audit_hook` (package `audithook`) turns billing events into audit records and hands each to a `Recorder` you provide. The interface matches Chronicle's emitter, so a small adapter over [Chronicle](https://github.com/xraph/chronicle) works, as does a plain function:

```go
recorder := audithook.RecorderFunc(func(ctx context.Context, ev *audithook.AuditEvent) error {
	log.Printf("audit %s %s %s", ev.Action, ev.ResourceID, ev.Outcome)
	return nil
})

engine := ledger.New(store, ledger.WithPlugin(audithook.New(recorder,
	audithook.WithEnabledActions(audithook.ActionInvoicePaid, audithook.ActionQuotaExceeded),
)))
```

`WithEnabledActions` records only the actions you list, and `WithDisabledActions` records everything but those. `WithLogger` takes a go-utils `log.Logger`.

It records these actions:

| Action | From |
|--------|------|
| `plan.created`, `plan.updated`, `plan.archived` | The plan hooks |
| `subscription.created` | `OnSubscriptionCreated` |
| `subscription.upgraded` | `OnSubscriptionChanged`, for every plan change: it doesn't compare the plans |
| `subscription.canceled`, `subscription.cancel_scheduled` | The cancel hooks |
| `subscription.renewed`, `subscription.trial_ended` | The lifecycle hooks |
| `invoice.generated`, `invoice.finalized`, `invoice.paid`, `invoice.voided`, `invoice.past_due` | The invoice hooks |
| `quota.exceeded` | `OnQuotaExceeded` |

The package declares more action constants (`subscription.downgraded`, `subscription.expired`, `usage.ingested`, `usage.flushed`, `entitlement.checked`, `entitlement.denied`, `soft_limit.reached`, `invoice.failed`, `provider.sync`, `webhook.received`, `webhook.processed`), but nothing records them today.

### observability

The engine records its own spans and metrics without any plugin (see [Observability](/docs/guides/observability)), so you only need this one for its dotted counters. `github.com/xraph/ledger/observability` counts billing events through a factory you provide:

```go
type MetricFactory interface {
	Counter(name string) Counter     // Counter: Inc(), Add(float64)
	Histogram(name string) Histogram // Histogram: Observe(float64)
}

engine := ledger.New(store, ledger.WithPlugin(observability.NewMetricsExtension(factory)))
```

These metrics move:

| Metric | Type | Counts |
|--------|------|--------|
| `ledger.plan.created`, `ledger.plan.updated`, `ledger.plan.archived` | counter | Plan hooks |
| `ledger.subscription.created` | counter | New subscriptions |
| `ledger.subscription.upgraded` | counter | Every plan change, whichever direction |
| `ledger.subscription.canceled` | counter | Cancels that took effect |
| `ledger.subscription.cancel_scheduled` | counter | Scheduled cancels |
| `ledger.subscription.renewed` | counter | Period moves by the clock |
| `ledger.subscription.trial_ended` | counter | Trials the clock ended |
| `ledger.usage.flush.latency_ms` | histogram | Meter batch write time |
| `ledger.entitlement.checks` | counter | Computed metered and seat answers |
| `ledger.entitlement.denied` | counter | "quota exceeded" answers |
| `ledger.invoice.generated`, `ledger.invoice.finalized`, `ledger.invoice.paid` | counter | Invoice hooks |
| `ledger.invoice.past_due` | counter | Invoices the clock marked past due |
| `ledger.provider.sync.success`, `ledger.provider.sync.failure` | counter | Provider syncs and imports |

It also creates `ledger.subscription.downgraded`, `ledger.subscription.expired`, `ledger.usage.events.ingested`, `ledger.usage.batch.size`, `ledger.entitlement.cache.hits`, `ledger.entitlement.cache.misses`, `ledger.entitlement.latency_ms`, `ledger.invoice.voided`, `ledger.invoice.total_amount`, `ledger.webhook.received`, `ledger.webhook.processed`, `ledger.store.errors` and `ledger.plugin.errors`, which stay at zero: no hook it implements updates them, or the hook that would never fires.
