---
title: PostgreSQL Store
description: The PostgreSQL store, on Grove's pgdriver.
---

`store/postgres` implements `store.Store` on a `*grove.DB` opened with Grove's PostgreSQL driver. It's the store to run in production.

## Setup

```go
import (
	"github.com/xraph/grove"
	"github.com/xraph/grove/drivers/pgdriver"
	"github.com/xraph/ledger"
	"github.com/xraph/ledger/store/postgres"
)

pg := pgdriver.New()
if err := pg.Open(ctx, os.Getenv("DATABASE_URL")); err != nil {
	log.Fatal(err)
}

db, err := grove.Open(pg)
if err != nil {
	log.Fatal(err)
}

engine := ledger.New(postgres.New(db))
if err := engine.Start(ctx); err != nil { // migrates first
	log.Fatal(err)
}
defer engine.Stop()
```

`pgdriver.New()` returns an unconnected driver, and `Open(ctx, dsn, ...)` connects it. `grove.Open` wraps the driver in a `*grove.DB`, and `postgres.New(db)` takes that.

`engine.Stop()` closes the store, and the store's `Close` closes the `*grove.DB`. Don't close the database yourself as well, and don't share one `*grove.DB` between a Ledger engine and code that outlives it.

## Migrations

`engine.Start` calls the store's `Migrate`, which runs the `postgres.Migrations` group through Grove's migration orchestrator. Grove records which migrations have run, so it's safe on every start. To migrate on your own schedule, pass `ledger.WithoutMigrate()` to the engine and call `Migrate` yourself:

```go
s := postgres.New(db)
if err := s.Migrate(ctx); err != nil {
	log.Fatal(err)
}

engine := ledger.New(s, ledger.WithoutMigrate())
```

## Tables

| Table | Holds |
|-------|-------|
| `ledger_plans` | Plans, with `features`, `pricing` and `credits` as JSONB |
| `ledger_features` | The feature catalog |
| `ledger_subscriptions` | Subscriptions, with period, trial, cancel, pause and seat columns |
| `ledger_usage_events` | Usage events |
| `ledger_entitlement_cache` | Cached quota answers, with an `expires_at` |
| `ledger_invoices` | Invoices, with `line_items` as JSONB |
| `ledger_coupons` | Coupons and their redemption counts |
| `ledger_coupon_applications` | Which coupon is on which subscription |

Plans, catalog features and coupons carry `app_id`, with unique indexes on `(slug, app_id)`, `(key, app_id)` and `(code, app_id)`. Subscriptions, invoices and usage events carry `tenant_id` and `app_id`, with indexes that lead with both. Usage events have a partial unique index on `idempotency_key` where the key isn't empty, and a duplicate key is skipped on insert.

## Isolation

The store filters by the tenant and app the engine passes it, and an empty tenant means every tenant. There's no row-level security. See [Multi-tenancy](/docs/concepts/multi-tenancy).

## Characteristics

| Aspect | Detail |
|--------|--------|
| Driver | Grove with `pgdriver` |
| Migrations | `postgres.Migrations`, run by `Migrate` |
| Coupon redemption | Cap check, count and application written as one unit |
| Lifecycle writes | Conditional updates, so several replicas can run the lifecycle clock |
| `Ping` | `db.Ping(ctx)` |
| `Close` | Closes the `*grove.DB` |

## Testing against it

The conformance suite in `store/storetest` runs against PostgreSQL when `LEDGER_TEST_POSTGRES_DSN` is set, and skips otherwise:

```bash
LEDGER_TEST_POSTGRES_DSN=postgres://... go test ./store/postgres/...
```

See [Memory store](/docs/stores/memory) for how the stores compare.
